# Architecture and module layout

The module-by-module map of the code, kept out of [AGENTS.md](../AGENTS.md) so that file stays short. The shorter overview is in [development.md](development.md#development).

- `hlp.py`: thin launcher; all logic lives in `homelab_probe/`.
- `homelab_probe/config.py`: env/`.env` loading. `client.py`: `UniFiClient`, the only place that makes HTTP calls. `snapshot.py`: `collect_snapshot(client, site, Needs(...))`, the one read of the controller; a command declares what it reads with a `Needs` (and an `EventQuery` for the event log), never with loose flags. `export.py`, `query.py`, `reservations.py`, `new_clients.py`, `client_view.py`, `events.py`, `wan.py`, `firewall.py`, `audit.py`, `wifi.py`, `topology.py`, `topology_graph.py` (the document as a Mermaid flowchart or a DOT digraph: ids are generated, every label is quoted and escaped for its syntax, `tests/test_topology_graph.py` checks each output line against a strict grammar), `history.py` and the `diagnose/` package: pure functions over a `Snapshot`. `diagnose/` has one module per topic (`devices`, `health`, `addresses`, `reserved`, `ports`, `wireless`, `event_checks`, plus `model` for severities, codes and `Finding`, `output`, and `areas`); a new check is a function in the module of its topic, a code in `model.CODES`, and one line in `areas.CHECKS` with every area it can emit (the order there is part of the output). `areas.py` maps code prefixes to the areas of `diagnose --only/--skip` (`devices`, `health`, `wan`, `clients`, `reservations`, `ports`, `wifi`, `events`) and `needs_for` says what a selection reads: a new code needs its prefix in `AREAS`, and a check that starts using new snapshot data must be reflected in `needs_for` (`tests/test_diagnose_areas.py` runs every area on the minimal reads and compares with the full run, so a missing read fails). `util.py`: shared helpers: output safety (`printable`, `clean_data`, `safe_output`, `csv_safe`) and small value helpers (`number`, `number_or_zero`, `known_percent`, `plural`, `normalize_mac`, `hex_digits`, `epoch_text`, `format_time`, `search_rows`, `is_randomized_mac`, `describe_age`). `demo/`: the synthetic controller (`controller.json` plus `DemoSession`, which the tests call `FakeSession`; `demo_config`/`demo_client` build the configuration and client of `--demo`). `documents.py`: documents, the layer between reading and printing (`Document(name, data, warnings)`: `data` is the dict `--json` prints, `x_document(client, site, params, settings, echo)` reads the snapshot with the command's `Needs` constant inside `logs.collect_warnings` and builds it; `wan`, `wifi`, `topology`, `firewall`, `audit`, `events`, `client`, `query`, `new-clients`, `diagnose`, `snapshot`, `diff`, `export`, `info` and `doctor` are converted (every command), and `dashboard` is a document with no command (API only); `diagnose` also has `meta["complete"]` (False when an optional read failed, which `--watch` skips), and `--notify` and `--watch` take their `Finding`s from `findings_from_document(document.data)`; `data` is a list for a `--json` that is a bare array, and `meta` carries what only the text view needs (`events`: `more`, `cap_truncated`; `client`: the `matches` when it is not exactly one; `query`: `kind`, `offline`); `audit` builds its document with `diagnose.findings_document` and renders it with `render_findings`, which #181 reuses for `diagnose`). `serve` network exposure (`--host`, `--allowed-host`, `--forwarded-allow-ips`; the helpers `util.check_bind`/`parse_allowed_host`/`parse_forwarded_ips` run without the extra: a wildcard bind needs an allowed host, the `Host` list is never a wildcard, `*` is never a trusted proxy, and the default trusts no forwarded header), `server/auth.py` (login: `guard` is the dependency of the **whole app** and lets through only the endpoints marked `@public`, so a route nobody declared needs a session; `admin` adds the stricter role; `OriginGuard` is a middleware refusing an unsafe request whose `Origin` is not the `Host` or whose body is not JSON; `sessions.SessionStore` keeps hashes of the cookie values in memory and re-checks the account, its role and a fingerprint of its password hash on every request; `throttle.LoginThrottle`; never write a typed username that is not an account, a password or a session id to a log or the audit trail; `app.routes` shows FastAPI's included routers as opaque objects, so enumerate routes through the OpenAPI document, not `isinstance(r, APIRoute)`), `server/` (the `web` extra: `fastapi`, `uvicorn`; the core never imports it, `tests/test_server_boundary.py` checks that, and `hlp serve` imports `server.runner` inside its handler): `app.create_app` (the factory), `security` (the `Host` allow-list, the headers on every response; the bind and proxy checks are `util.check_bind`, `bind_host_name`, `parse_allowed_host` and `parse_forwarded_ips`, so the command checks `--host`, `--allowed-host` and `--forwarded-allow-ips` without the extra, and `allowed_hosts` re-validates its input so a caller that skips argparse cannot open the list), the request log (`server.request`, the route template, never the path), `runner.run`, `routes` (one GET per document; each calls the document function the command calls through `ControllerService.build`, validates its parameters like the CLI and returns the document plus `generated_at`/`warnings`, or `{items, ...}` for a bare array; a route never takes a path to forward, and an error is `errors.ApiError` with a fixed sentence, never an exception's text), `apischema` (the schemas of `docs/schemas`, shipped in the wheel as `homelab_probe/schemas` through `[tool.setuptools.package-dir]`, so `[tool.setuptools] packages` is a hand-kept list that `tests/test_accuracy.py` checks; `tests/golden/openapi.json` is the OpenAPI snapshot: `UPDATE_GOLDEN=1 uv run pytest tests/test_server_routes.py`), `cache.ResponseCache` (a TTL, single-flight per key, stale-on-error, error coalescing, a cap on reads in flight; answers are deep-copied in and out) and `service.ControllerService` (a `CachingClient` per document build, sharing one cookie-less session and the cache; `CachingClient` overrides only `_get` and `_post_system_log`, so documents and snapshots are unchanged and a new read needs no server code; `build()` returns the document with `generated_at` and warnings). Tests use `fastapi.testclient` with `httpx2`, and CI syncs the extra everywhere except the `base-install` job. `setup.py`: the engine of the guided setup, shared by `hlp init` and the web wizard (core, no new dependency; validates one setting at a time with the validators the commands use, merges settings into an existing `.env` keeping everything else, writes owner-only files atomically with a `.bak`, refuses symlinks, values with a line break or `${`, and never puts a secret in a result or message; `config.build_config`/`read_env_values`/`layered_values` are the pure readers it and the server's reload use, `doctor.check_controller` the connection test). `tlsprobe.py`: the setup's two TLS steps (`fetch_certificate` completes an unverified handshake and sends nothing, `check_pin` trusts only that certificate through the context `requests` builds for `verify=<file>`, `resolve_target` refuses addresses no controller has and every address a name resolves to must pass; failures are `ProbeError` with a fixed `reason`, never library text; the test servers are `tests/tls_fixtures.py`, whose keys are stored without their PEM header lines so no file looks like a leaked key). `server/wizard.py`: the setup mode of a server with no usable settings (`SetupState` holds the token and the in-memory `Draft`; `auth.setup_ok` marks the seven setup endpoints, which `guard` lets through while `app.state.setup.mode` is set and every other endpoint answers 503 `not_configured`; `setup_access` wants the `X-Setup-Token` (throttled and audited like a login, via the `(setup)` actor) while no enabled administrator exists and an administrator's session otherwise, or once `mode` is None; setup mode applies only when neither `UNIFI_URL` nor `UNIFI_API_KEY` is set, broken settings stay a loud start-up error (owner decision, #185); link-local addresses are refused even though the issue text lists them, because 169.254.169.254 is the cloud metadata address, and `--allow-public-controller` is the opt-in for public ones; the key is registered with `logs.register_secrets` on arrival and never returned; connection tests use `max_redirects = 0` and fixed-word results; `runner.resolve_config` reads `--env-file` > `HLP_ENV` > `<data-dir>/.env` plus the environment without mutating it, and `serve` is a `run_local` command for that reason; `commands.apply_logging` is the secret registration and log setup `cli.main` also uses). `/finish` writes through `setup.apply` (plus `certs/controller.pem`), creates the administrator last, reloads through `SetupState.reload` (the closure `commands._run_serve` gives `runner.run`: the same resolution and `--timeout`/`--parallel` overrides as at start), starts a `ControllerService` and sets `mode` to None; when the environment, `--env-file`/`HLP_ENV` or the volume would defeat the saved file it writes nothing and returns the finished `.env` and compose snippet with `setup.PLACEHOLDER_KEY` instead of the key (the key is never returned, owner decision #185). A configured server with no enabled administrator starts in `MODE_ADMIN` (only `status` and `finish`; `runner.run` makes the state) instead of exiting. `server/settings_api.py`: `GET`/`PUT /api/v1/settings` edit the same `hlp.toml` the CLI reads (`settings_file`: `--config`, else `<data-dir>/hlp.toml`, which the report routes use too): the change is applied to the text with `tomlkit` (the `web` extra, never imported by the core), written to a temp file named `hlp.toml` and loaded with `settings.load_settings` (its message is the 422), a `version` hash detects an edit made meanwhile (checked again just before the write, under a lock), the old file is `.bak`, permissions are kept, a symlink is refused, a no-op writes nothing; a write route is marked `@local_write` and `serve --read-only` makes `refuse_if_read_only` answer 403 for it (`tests/test_server_read_only.py` lists every unsafe route and fails on one that is neither marked nor on its `WRITES_NOTHING` list). `server/snapshots_api.py`: `GET`/`POST .../snapshots` and `GET .../diff` over the files `snapshot`/`diff` use (`history.site_snapshots`, `find_snapshot`, `snapshot_summary`; the site is resolved first through the cached `client.resolve_site`, its id names the directory; a snapshot is addressed only by a name that passes `history.is_snapshot_name`, so no caller path is opened; the save refreshes the cache first, runs under a lock with its prune, is `@local_write` and admin-only and audited as `snapshot.saved`). `routes.respond` and `routes.checked_site` are the shared helpers of the site routes. `server/profile_api.py`: `POST /api/v1/auth/password` (any logged-in user, CSRF, `@local_write`; `AccountStore.change_password` verifies the current password and changes it in one step under the lock, policy first so a rule violation says nothing about the current password and costs no throttle attempt; wrong guesses go through the login `LoginThrottle` (`auth.refuse_if_throttled`); `SessionStore.renew` ends every session of the user and gives the caller a new cookie and CSRF token with the same start; `LocalAccounts.can_change_password` is what `session_document` reports in `/auth/me`; audit `user.password_changed`, `auth.password_failed`, never a password). `server/users_api.py`: `/api/v1/users` (admin-only, `@local_write`) over `AccountStore`; `accounts.py` raises typed errors (`PolicyError`, `UserExistsError`, `NoSuchUserError`, `LastAdministratorError`, `AdministratorExistsError`, `AuditWriteError`, all `AccountError`) so the API maps them by kind and never by message (`PolicyError.code` picks a fixed sentence in `errors.POLICY_MESSAGES`; never pass `str(error)` of an account error to a response), and `AccountStore.update(username, role, disabled, on_change(old, new))` changes both fields atomically; `errors.ERROR_SCHEMA`/`error_responses(..., text={404: ...})` build the error entries of the OpenAPI document with the wording of each route. `server/scheduler.py`: `serve --scheduler` runs the diagnose and snapshot jobs on a thread (`Scheduler.tick()` is the testable unit with an injectable clock; it never raises: a job failure is a `JobResult` with a fixed reason). The notification step is `notify.process`, shared with `diagnose --notify` and taken under `util.file_lock` on `<state>.lock` (a scheduler and cron never both announce; `baseline_if_new` makes the first scheduled run baseline instead of announcing all; the scheduler skips the state entirely on a partial read and never writes it through a symlink); `snapshots_api.store_snapshot` is the save-and-prune shared with the route. Run records are `scheduler.run` events with a fixed reason: never put a message, name or address in one. `server/status_api.py`: `GET /api/v1/status` reports only what the server has seen (`ResponseCache.wire` records the outcome of every wire read: a connection, timeout or TLS failure or a refused key is a connectivity state, an error status is still an answer; `ControllerService.last_warnings`; `Scheduler.status()`; `Deliveries` for the scheduler's and the test's deliveries; `storage()` probes in fixed words); viewers get the summary, administrators the kinds, reasons, destinations, storage and `problems`; it never makes a controller request, and no address, path, URL, token or message may be in it. `POST /api/v1/notifications/test` (admin, CSRF, 10 s apart) calls `notify.send(..., test=True)`, which sends the fixed test message (a webhook gets `"test": true` and no events). `triage.py` (stdlib only) and `server/findings_api.py`: `finding_id` is a hash of the code and the MAC (through `normalize_mac`) or else the lower-cased subject; `TriageStore` keeps `snapshots/<site id>/triage.json` (ids, codes, states, who/when, first/last seen: **never a name, MAC or address**; atomic, locked, symlink-refusing, refuses another site's file); `reconcile` ends an entry only for a **complete** read and never on a partial or failed one (the scheduler calls it); `rank_findings` is pure and deterministic and returns the reasons and the limitations (persistence is used only where a record exists); acknowledged and snoozed findings stay in the list. `GET .../findings` never writes; a damaged or linked triage file degrades to `triage_available: false`. `search.py` (pure, over a `Snapshot`, its findings and the subjects of `NotesStore.subjects()`) and `server/search_api.py` (`GET .../sites/{site}/search`, not a document: it has its own inline schema like the findings list): `SEARCH_NEEDS` is `needs_for(None, ...)` plus `offline`, `wlans` and `networks` (the findings list's read, so the cache answers it; `tests/test_search.py` pins the reads), a query is text (substring, never a pattern), a MAC in any spelling (`util.hex_digits`, at least four digits) or an IP (`normalize_ip`, whole addresses by canonical form); hits carry the controller's strings **verbatim** and are ordered by match quality, label and key; the limit is per kind with `kinds[kind].total/shown` and `truncated`; an unreadable source is in `unavailable` and makes `complete` false (never "no hit"); notes come from the resolved site's own file and a damaged, linked or other-site file degrades to `unavailable: ["note"]`; a new kind needs a case in `tests/test_search.py` and the route's schema; the search text is never logged. `dashboard.py` and `server/dashboard_api.py` (#244; the one document with no command: `documents.dashboard_document`, `GET .../dashboard`): `build_dashboard(snap, settings, entries, now, today, stale)` is pure over the snapshot of a full `diagnose` (`DASHBOARD_NEEDS = needs_for(None, 24h)`, pinned by `tests/test_dashboard.py` against the reads of `diagnose`) and reuses `diagnose`, `build_wan`, `wifi.radios`, `build_offline_clients` and `triage.rank_findings`; `status` is `ok` only for a complete, not-stale read of a controller that answered (a partial, stale or unreachable one is `unknown`, a critical or warning finding wins whatever its triage state), every section has `available` (False: not read, never zero) and a count whose source is missing is `null` (`Snapshot.all_users_available` is False only when `stat/alluser` was requested and failed, so an empty history that was read is an answer; `stale_state` picks by a fixed precedence, key_rejected > certificate > unreachable, because parallel reads report their kinds in completion order); a controller that cannot be connected to (`dashboard.connection_state`: connection, timeout, tls, unauthorized, forbidden) is a 200 `unreachable_dashboard` and any other `UniFiAPIError` is raised as for the other documents; the triage file is read through a `triage(site_record)` callable the route passes (`StoreError` makes `by_state` null), and staleness through `server.cache.stale_served` (`track_stale` in `ControllerService.build` collects the `kind` of every failed read answered from an older cache; documents never import `server/`). `groups.py` (stdlib only, issue #230): `group_findings(findings, links)` gives each `device.offline` finding that an offline uplink explains a `group` (`kind` `offline_behind_offline_uplink`, the `cause` finding id, the evidence chain and `limitations`); `links` is `topology.device_links(snap)`, which `diagnose_document` puts in `meta["links"]` (no extra read, so `Needs` is unchanged). The cause is the root-most offline ancestor that has a finding of its own; no group for no known uplink, an online or unknown-state parent, an offline ancestor without a finding, or a loop (an offline device keeps its last known uplink, so the claim is "probably" and says so). Nothing is hidden or re-ranked: `group` is `null` on every other finding, and `item_of(r, group)` is the one representation for the list and for the `PUT .../triage` answer. A new kind of group is a new `kind` in `groups.py`, its text in `docs/web.md` and a case in `tests/test_groups.py`. `sitefile.py` (stdlib only) is the base of the per-site JSON files (`SiteFile`: link refusal, lock, atomic owner-only write, `{version, site, entries}`, another site's file refused; `StoreError` has a fixed `code`), which `TriageStore` and `notes.NotesStore` extend; `notes.py` keeps `snapshots/<site id>/notes.json` (a subject is `device:`/`client:` plus a MAC through `normalize_mac`, or `finding:` plus a finding id, **never a name**, so a note follows a rename; text cleaned, 4000 characters, never interpreted as markup; an edit needs the `revision` it read, else `conflict`; `subjects()` lists retained subjects with their last-known name, independent of the inventory) and `server/notes_api.py` serves it (admin + CSRF + `@local_write`; audit by note id and subject kind only; a store method is `remove`, never `delete`). `backup.py` (stdlib only, issue #226) is the archive of the application's own state: `classify` is the one table of allowed member names (a name no category allows never gets in), `live_files`/`collect` read the data directory under the accounts and per-site locks and refuse a link, `pack`/`unpack` make and check the ZIP and its manifest (`FORMAT`, `DATA_FORMAT`, `SUPPORTED_DATA_FORMATS`), `inspect` checks every file with the readers the application uses (`accounts.parse_users`, `SiteFile.parse`, `load_settings`) and refuses a backup without an enabled administrator or a per-site file naming another site than its directory, and `preview` is the secret-free answer (names of settings, never values); `BackupError` has a code and a fixed message. `server/backup_crypto.py` (the only `cryptography` import; scrypt and AES-256-GCM, header authenticated, parameters bounded before use) and `server/backup_api.py` (export and preview; admin + CSRF; neither is `@local_write` because they change nothing, so they work with `--read-only`; never put the passphrase in a log, an audit field, an error or a URL; two at a time). A new category goes in `backup._RULES` and `inspect`, and a change to what the files mean needs a new `DATA_FORMAT` and a migration. `restore.py` (stdlib only) restores one: `plan` (the replacement set; an optional category is only added to; audit goes to `audit-imports/`), `apply` (journal `restore-journal.json` in `staging`, new files staged as `<name>.restore-new`, journal `applying` = the commit point, then each file is moved to `<name>.restore-old` and the new one renamed in; every step is repeatable), `recover` (run by `commands._run_serve` before the settings are read: staging is discarded, applying is completed or, failing that, undone; neither stops the start with exit 3), `write_recovery`/`prune_recovery` (`recovery/`, newest three, never while a journal exists); `restore.FAULT` is the test hook that simulates a crash at each step (`tests/test_restore.py` runs every step), and a new step needs a `_fault` call. `server/restore_api.py` is the route (`@setup_ok` + `@local_write`, `setup_access`: an administrator or the setup token; `Maintenance` makes one restore at a time, `refuse_if_read_only` answers 503 `restore_in_progress` for a file-writing route meanwhile and `Scheduler.ready` is false; it holds `backup.locked(...)` (`LOCKED_NAMES`: users, notes, triage, `.env`, the settings file, which `setup.apply` and the settings PUT take too) and `Scheduler.idle()` while it collects the recovery backup and applies, so a writer that takes the same locks waits: do not log in or write from inside it); afterwards `SessionStore.end_all`, the reload (`app.state.reload`, `wizard.reload_default`) and a new `ControllerService`. A new setup route needs `@setup_ok`, a case in `tests/test_server_setup.py` and an audit event named in `docs/web.md`. `accounts.py`: the accounts of the web interface and the `web-user` command (standard library only; `AccountStore` keeps `users.json` under a lock file with atomic writes, scrypt hashes carry their parameters and are upgraded at login, the last enabled admin is protected inside `AccountStore._change` so no path bypasses it, `LocalAccounts` is the first `Authenticator`; `AuditLog` writes the rotated, owner-only `audit.log`; a store method is never named `delete`, `tests/test_events.py` greps the package for HTTP verbs; a new audit action goes in `docs/web.md`). `doctor.py`: the `doctor` checks of the tool's own setup (a `Check` has a stable `id` from `CHECKS`, a status and a message built from fixed words; it runs with `Command.run_local` because a broken configuration is what it reports, and never repeats an address or a secret: a failed request is explained from `UniFiAPIError.kind`, not from its text). `logs.py`: the `homelab_probe` logger tree (formats `cli`, `text`, `json`; the redaction filter; request ids; `EVENTS`; `warn` and `collect_warnings`). `notify.py`: notifications (plan what changed, wording, the one outbound `requests.post`, state file). `watch.py`: `diagnose --watch` (what changed since the last pass, from `notify.plan` with an in-memory state; the loop and its injectable `commands.WATCH_SLEEP` are in `commands.py`; never combined with `--json` or `--notify`, and it must not write or send anything). `settings.py`: `diagnose` thresholds and ignore rules from an optional TOML file; new checks take their thresholds from `DiagnoseSettings`, never module constants. `cli.py`: the argument parser and `main` (config, client, then the command's handler). `present.py` (issue #233; stdlib plus the optional `pretty` extra, Rich, imported only there and lazily): the one terminal presentation policy. `cli.main` builds `Presentation.from_args(args)` from the global `--color auto|always|never`, `--no-progress` and `--plain` and passes it as `Context.present` (a `Context` built without one gets `Presentation(plain=True)`, never the automatic policy; `run_local` commands get no `Context`). Never test `isatty`, `NO_COLOR` or `TERM` in a command: ask `present.print(*parts, stream=...)` (the styled print path: `commands.say` strips escapes, so styled text never goes through it), `present.style(text, role, stream)`, `decorations(stream)`, `symbol(name, stream)`, `progress_enabled(stream)` or `console(stream)` (a Rich console, `None` when Rich is missing, `--plain` or machine output). `progress.py` (issue #234) is the transient progress line on stderr: `cli.main` runs the handler inside `Progress(present, enabled=eligible(args))` (`ELIGIBLE` names the commands; `--watch` and `--notify` never) and sets `client.stage`/`client.note` (silent no-ops by default); the work reports its real boundaries with `client.stage("Reading devices")` (fixed phrases, never text from the network; `collect_snapshot`, `collect_event_snapshot` and the documents do) and a new stage goes where the work really waits; `logs.STDERR_GUARD` makes every log write erase the line first, and `commands.say` and `Presentation.print` call `progress.finish()` so output never shares the screen with a spinner. No percentage, bar or estimate: the total is not known. Tests drive `tick()` with a fake clock. `pretty.py` (issue #235) renders the documents on a terminal and nowhere else: handlers call `pretty.print_findings`/`print_table` only when `ctx.present.decorations(sys.stdout)` is true, so plain, `--json`, `--csv`, goldens and exit codes do not change; network text goes through `util.printable` (one line, no controls) before `present.print`, the text under a finding is behind a bar so a wrapped message cannot forge a finding line, "No issues found" is green only for a complete read, and a table that does not fit becomes stacked rows (nothing is cut). stdout and stderr are decided separately; color precedence is `--plain`, machine output, Rich missing, `--color never`, `--color always`, `NO_COLOR`, not a terminal, `TERM=dumb` (`color_reason` names the step); `--json`, `--csv`, `topology --format mermaid|dot`, `export` and `completion` (`MACHINE_COMMANDS`/`MACHINE_FLAGS`/`MACHINE_FORMATS`) are never styled whatever is forced, and a new machine-output flag or command goes there. Text from the network is data: `style` cleans it with `safe_output` and renders `rich.text.Text`, never markup, and every console is built with markup, highlight and emoji off. A path that needs Rich is tested with `pytest.importorskip("rich")` and the missing-Rich path with `sys.modules["rich"] = None`, so the suite passes with and without the extra and the Coverage job (which syncs the `pretty` extra) reaches 100%; the plain output of every command must stay byte-identical (goldens). `commands.py`: one section per subcommand (its arguments, its checks, its handler, the `Needs` it declares) and the `COMMANDS` registry.
- Container image (#246, `docs/docker.md`): `Dockerfile` (stage 1 `web` is a **placeholder** that leaves the bundle in `/out`, only that stage changes when the React build arrives, and it is copied into `homelab_probe/web` only when it is not empty; stage 2 builds wheels of `.[web]`; the last stage installs only those wheels as uid 10001 with `/data` as `WORKDIR` and `VOLUME`, `ENTRYPOINT ["hlp"]`, default `CMD serve --host 0.0.0.0 --allowed-host localhost --scheduler`: a wildcard bind needs an allowed host, `localhost` is accepted anyway, so the default answers only the machine that publishes the port; compose's `command:` replaces the whole default), `compose.yaml` (127.0.0.1 port, read-only root, tmpfs `/tmp`, `cap_drop` ALL, no setup token, never a key), `.dockerignore` (excludes everything, then whitelists only what the `COPY` lines name: a new `COPY` source needs a `!` line), `tools/docker_smoke.sh` (what the `docker` CI job runs on the built image; no push, no login, no `packages: write`: publishing to GHCR on a `v*` tag is part 2 of #188) and `tests/test_docker_files.py` (checks all of it without Docker). A new file the image needs goes in the `COPY` lines, `.dockerignore` and that test together.
- `tools/`: development scripts that are not part of the package: `record_fixture.py` (records a real controller into a sanitised fixture) and `sanitize.py` (the deterministic sanitiser and its leak check). `tests/contract.py` is the one table of the fields the code reads from each endpoint (also the request guard `RecordingSession` and `endpoint_of`); `tests/field_tracking.py` derives that list from what the code actually touches. `build_docs.py` builds the docs bundle (`docs.json`, #243) for the web interface's Docs page from `README.md`, `docs/*.md` and `docs/schemas/*.json` (stdlib only; a block classifier for the approved Markdown subset, not a renderer; it fails the build on raw HTML other than comments and `<a id>` anchors, on constructs outside the subset, on missing images and on broken links or anchors, and reads nothing outside the repository; its `slugify`/`anchors_of` are the one GitHub-anchor implementation, which `tests/docs_support.py` reuses; a new docs page needs only its file, and a place in `GROUPS` to be grouped; markdown you write in `README.md` or `docs/` must stay inside that subset, `tests/test_build_docs.py` builds the real docs). `tests/contract.py` is the one table of the fields the code reads from each endpoint (also the request guard `RecordingSession` and `endpoint_of`); `tests/field_tracking.py` derives that list from what the code actually touches.
- `web/`: the browser UI (issue #240; its own npm project: React, TypeScript strict, Vite, React Router, TanStack Query, Vitest, Playwright; **nothing from it reaches the Python package or its runtime requirements**, and its build writes only to `web/dist`, ignored by the VCS; copying a build into the package is the serving/release work, not this directory's). `src/generated/` is `json-schema-to-typescript` output of `docs/schemas` (commit it with every schema change: `npm run check:types` in the CI `web` job regenerates and fails on a difference); `src/api/` is the one fetch client (same origin, CSRF token from login/me in memory only, one `ApiError` from `{error, message}`, a 401 ends the session in the UI); `src/test/fakeApi.ts` is the fake server for Vitest and may serve only routes in `tests/golden/openapi.json`, with the real order of origin check, 401, role, CSRF and the login throttle; `src/lib/safeText.ts` ports `util.printable` and is checked against `src/lib/printable-vectors.json`, whose answers `tests/test_web_printable_vectors.py` recomputes with `printable` (a change to `printable` means regenerating the vectors and porting it); `src/theme/storage.ts` is the only code allowed to use browser storage (ESLint enforces that, and forbids `dangerouslySetInnerHTML`/`innerHTML`); the server's CSP allows only its own scripts and styles, so no inline script, inline style or external font/CDN. `e2e/serve.mjs` serves the build in front of the real servers listed in `E2E_SERVERS` (`demo`; `setup`: no settings; `admin`: settings for `https://controller.invalid` and no account, with a seeded note; `stub`, `fallback` (environment sets `UNIFI_VERIFY_SSL`) and `readonly` (`--read-only`): setup-mode servers for `setup-stub.spec.ts`; temporary data directories, `HLP_SETUP_TOKEN` chosen by the script) for Playwright (phone and desktop; `setup*.spec.ts` run only in the `setup-*` projects, each with its own servers because the tests change them). `e2e/stub_controller.py` is the stub controller those use: HTTPS on 127.0.0.1, the demo network, one random API key, a throwaway certificate of `tests/tls_fixtures.py` (loopback is an address the setup accepts). The e2e tests must never reach a real controller or send a notification. Brand (#267): dark is the default theme (`:root` in `tokens.css`, no attribute), `light` and `system` set `data-theme` (the light set is written twice and `tokens.test.ts` checks they agree); the shell renders the header navigation and account menu on a wide screen and the menu sheet below 56rem (`DESKTOP_QUERY`), so jsdom tests see the phone layout unless they stub `matchMedia`. The setup screens (`src/setup/`, `/setup`): the token lives in React state only, **no secret goes through `useMutation`** (its mutation cache keeps the variables: use `useAction` from `src/lib/useAction.ts`, which `useSetupMutation` and `useLogin` wrap; `setup.test.tsx` and `App.test.tsx` sweep the query client for poisoned values and a test forbids `useMutation` in `src/setup/`), and the page sends **no setup request before the token is typed** (the server counts a token-less request as a failed attempt; only an administrator who logged in on this page probes without one); secrets (API key, notification values, passphrases) are sent once and the fields emptied; `src/test/fakeSetup.ts` fakes the setup and restore routes on `FakeApi`, whose `route(..., {setup: true})` checks the token while no enabled administrator exists, and an administrator's session and CSRF token otherwise. Write non-ASCII or hidden characters in web test files as escapes. Run `npm ci && npm run check && npm run e2e` in `web/` before a web PR; docs are in `docs/development.md` ("The web interface") and `docs/web.md`.
- `server/static.py`: serves the built Vite bundle with an SPA fallback, strict path checks and descriptor-based no-follow opens; sets the web CSP only on bundle responses.
- Terminal API (#270): `server/terminal_policy.py` pins the allowlist and CLI grammar parity; `terminal_api.py` enforces bounded authenticated wire contracts and admission; `terminal_reports.py` has fixed report adapters; `terminal_completion.py` suggests only request-local, role-filtered parser/registry metadata, never calling a handler or service. Completion consumes the same admission budget as execute but releases synchronously. Execute workers retain their slots after HTTP timeout/disconnect. The schemas in `docs/terminal/`, generated web types and `web/src/test/fixtures/terminal.v1.json` form the [frontend handoff](web.md#frontend-handoff).
- Browser terminal engine (#275): `web/src/terminal/engine/types.ts` is the panel/integration contract; `index.ts` exports the pure `engine` transitions and execution gate. `lexical.ts` retains token source ranges and quotes literals, `suggestions.ts` consumes capabilities without a command allowlist, `input.ts` decodes streamed key/paste frames with explicit caller-owned bounded state, and `line.ts` uses `Intl.Segmenter` plus frontend-only `string-width` for grapheme boundaries and cell-width wrapping. `engine.test.ts` runs in Node, without a DOM or xterm. No panel or API execution is enabled here; #276 and #277 own those integrations.
- Browser terminal integration (#277): `web/src/terminal/api.ts` implements the backend contract using the shared same-origin API client, runtime validation, request-ID matching and bounded waiting without retries or query caching. `useTerminalSession.ts` owns abort controllers and completion debounce, drops disposed generations and stale execution results, and renders warnings separately. `Shell.tsx` keys the dock by account identity/role so user changes dispose all terminal state. `main.tsx` provides real services only under `VITE_TERMINAL_API_PREVIEW=1`; normal builds stay disabled pending CSP approval and real-API browser acceptance.
- Terminal CSP feasibility (#277): `web/scripts/probe-terminal-csp.mjs` runs an isolated Chromium experiment on an ephemeral loopback server. It compares missing/correct/wrong style nonces, terminal-local style authorization, theme/resize/input behavior and denied unrelated styles/scripts. It does not change application headers or enable the terminal; findings and production requirements are in `docs/development.md`.
- New features are new subcommands: a section in `commands.py` (`_add_x` for the arguments, `_check_x` for combinations to reject, `_run_x(ctx) -> int` for the handler, which declares its `Needs`) plus one `Command(...)` row in `COMMANDS`, backed by modules that take a `Snapshot`; keep fetching (snapshot), analysis and output separate.
- Shell completion (`completion.py`): the bash, zsh and fish scripts are generated from the argument parser, so a new option needs nothing and a value argparse cannot express goes in `VALUE_HINTS`; the `completion` command is the command that runs through `Command.run_local`, before any `.env` is read, so it works on a machine with no configuration. `tests/test_completion.py` runs the bash script in a real bash and checks that every command and option is in every script.
